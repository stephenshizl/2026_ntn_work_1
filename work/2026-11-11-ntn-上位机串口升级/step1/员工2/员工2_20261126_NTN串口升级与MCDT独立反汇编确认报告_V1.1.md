## 1. 总结与新增确认

原始 MCDTV5(1).exe 已由项目经理直接提供，实际从原始文件用 GNU objdump 独立生成关键函数汇编，并直接从PE映像读取常量、跳转表和导入。此次解除V1.0的原始EXE不可读取阻塞项，不再依赖员工1汇编文本作为唯一依据。采用人工语义还原，不声称恢复原始C++源码或完成全部函数的Ghidra/IDA自动反编译。未运行EXE，未接触实板、未写Flash。

核心结果：
- 0x57写保护使用接收模式7（累计至少2字节），不是模式8（首字节06）；不能采用此前报告的单字节ACK假设。
- 0x7A头9B，LEN为BE32；0x79固定64KiB写入，头5B；旧路径和新路径均有30ms间隔证据。
- 0xEB地址+CHK，接收256B，不是读20B。
- 13档波特率索引直接由PE常量表确认；0x50响应走mode8，之后调用Sleep(500)再尝试本地改速，改速最多5次。
- NV PageCRC路径确认起始偏移4、循环长度取对象字段、初值FF、按U8/U16/U32类型写入CRC槽；员工3的422B编译输出尚未与原厂线上字节逐字节比对，暂不得作为烧录基线。
- 硬件可行性仍是原理图和既有报告证据，并非板级实测。项目优先完成厂家工具抓包再冻结协议。

## 3. 工程需求与硬件设计

目标：Windows PC → 产品RS232/J1/SP3232E → HC32F460 USART1 → MCU升级代理 → USART3 PB4/PB5 → U22电平转换 → MS150 UART0。主MCU控制PA10/PA8/PB15。仅升级MS150 E31/DSP等目标分区，不是主MCU自身升级、蓝牙/卫星OTA。

| 功能 | MCU | NTN侧 |
|---|---|---|
| TX | PB4 USART3 | UART0_RXD Pin32 |
| RX | PB5 USART3 | UART0_TXD Pin33 |
| BOOT | PA10 | Q4反相，MCU高有效、BOOTSEL低有效 |
| RESET | PA8 | Q3反相，MCU高有效、RESETN低有效 |
| 电源 | PB15 | 极性/时序须现场及源码核实 |

依据V1.0及员工1/3原理图审查，具备既有硬件升级基础。PC侧建议115200 8N1；不让外部RS232直接升至1.5Mbps。SP3232E具体后缀及速率上限存在报告分歧，以BOM实物为准。板内USART3高速及电平质量尚未实测。

主仓库Gitlink历史指向MCU commit 03b0abc3f4062178c1d5864100bdc98e9c87b905，指定分支work_v1_boot_fix；V1.0时独立GitHub仓库返回409 empty、branches=[]，本次未重新验证其最新推送状态。蓝牙、Android、Web不是本轮开发目标。MCU必须新增独占升级会话，避免AT/URC解析、正常透传、自动复位和收包线程争抢。历史hw_power_ntn_set(true)可能清除BOOT选择，需源码复核，不能直接照搬。

## 4. 协议逆向：原始EXE证据

证据状态：S=本轮原始EXE静态证据；D=厂家文档或历史报告，尚未独立完整定位；T=动态待测。S不意味着已验证模组线上响应。

### 4.1 端序与校验

0x140136B20写地址BE32；0x140136850读取LE32。0x14013CE00及0x14013D71F/74D/776追加XOR。初值FF，覆盖命令完整本体；整帧再XOR结果FF。内部string NUL不发送。人工语义伪代码：

```c
uint8_t chk(const uint8_t *p, size_t n) {
    uint8_t x = 0xff;
    while (n--) x ^= *p++;
    return x;
}
```

### 4.2 公共接收函数

0x14013D6D0发送助手，0x14013D7CE设置接收模式参数，0x14013D7D2设3000，0x14013D7E3调用接收函数0x14013DA70。3000为该路径参数，不等于所有操作固定3s超时。0x14013DB52加100000000ns，接收函数有等待/轮询机制；实际响应、超时与重试需分别抓包或跟踪。

直接读取原EXE 0x14013DF64索引表和0x14013DF3C跳转表，映射：

| 模式 | 跳转地址 | 条件 |
|---|---|---|
| 6 | 0x14013DD68 | 累计恰好256B |
| 7 | 0x14013DD40 | 累计至少2B |
| 8 | 0x14013DD36 | 首字节06 |
| 9 | 0x14013DD75 | 字符串搜索分支；不能当成通用ACK |

其他分支存在长度门槛15、12、23等，不能未经调用路径核实将其分配给具体命令。MCU使用独立缓冲和绝对deadline，处理串口分片、拼包、超时和意外字节。

### 4.3 0x57写保护勘误（S+T）

EXE常量0x14034A5C8为575680001806000001，0x14034A5E0为575680002400000200。0x14013E0CD/0x14013E1AF置校验标志1；0x14013E0D1/0x14013E1B3设置mode7；0x14013E126/0x14013E208调用0x14013D6D0。

TX完整帧：
- 57 56 80 00 18 06 00 00 01 61
- 57 56 80 00 24 00 00 02 00 58

员工3此前报告中的mode6/单字节ACK描述不成立；厂家文档描述文本回复。原EXE证明的是接收门槛，不是线上完整回复字节数或内容，不能据此采用任意2字节即协议成功的简化策略。第一条调用的返回处理和第二条返回分支亦不宜简单照抄为每条严格ACK。须捕获两条完整RX，确认文本、ACK、NACK及其先后关系，并定义消费边界、防止残留字节污染后续帧。

### 4.4 0x50波特率完整表（S+T）

0x14013CADD/CAEA/CAF7装载0x14034A630起48B（12个LE32），0x14013CB04写第13项4000000。0x14013CB41查表；0x14013CBD7生成50+index；0x14013CC1C/CC30算XOR；0x14013CC5E发送3B，0x14013CC7D设mode8，0x14013CC85超时参数3000，0x14013CC97收应答。

| index(hex) | baud | TX(hex) |
|---|---:|---|
| 00 | 9600 | 50 00 AF |
| 01 | 19200 | 50 01 AE |
| 02 | 38400 | 50 02 AD |
| 03 | 57600 | 50 03 AC |
| 04 | 115200 | 50 04 AB |
| 05 | 230400 | 50 05 AA |
| 06 | 460800 | 50 06 A9 |
| 07 | 921600 | 50 07 A8 |
| 08 | 1000000 | 50 08 A7 |
| 09 | 1500000 | 50 09 A6 |
| 0A | 2000000 | 50 0A A5 |
| 0B | 3000000 | 50 0B A4 |
| 0C | 4000000 | 50 0C A3 |

额外发现：0x14013CBAB比较57600，若相等跳过前置55时钟配置；其他目标速率执行55路径且mode8。不能把55必然视为每档都执行。
收到50应答后0x14013CD40设500，0x14013CD45调用0x140139CC0，其IAT 0x140317188对应Sleep。0x14013CD6C调用本地改速助手0x14013FC60；失败计数至5，成功退出。这里是**本地改速最多5次**，不是50命令重发5次。首次改速前等待500ms；应答实际在线速率仍须抓包。1.5M是板内目标值，13档表不代表板子均支持。

### 4.5 79/7A 写块（S+T）

旧路径0x14015D590：0x14015D5E0头长5，0x14015D5EF默认79；0x14015D72A比较65536；0x14015D732置7A，0x14015D73B/743/74B/751写4B BE长度，0x14015D754置头长9。新路径0x14016C860：0x14016C9F6比较65536，0x14016C9FF置7A，0x14016CA27置79，0x14016CA3F有9B头常量。

| 类型 | 报文 | 总长 |
|---|---|---|
| 79 | OP+ADDR_BE32+65536B DATA+CHK | 65542 |
| 7A | OP+ADDR_BE32+LEN_BE32+DATA+CHK | n+10 |

旧路径0x14015D961发送头，0x14015DB4A比较0x1C9C380=30000000ns；新路径0x14016CDD2传30到0x14016CDD7调用IAT 0x140319078（QThread::msleep）。两条路径独立支持30ms延时。新路径0x14016CDEE/CE14显示0x200主机发送块大小。不要把512B操作系统写块边界解释为模组ACK边界。MCU须先缓存完整块再发头，等待TX真正完成后延时，防止低速外部供数打断模组数据。实际时间容差及尾部应答仍待测。

### 4.6 EB读取页（S+T）

0x14015F9A2写EB，0x14015F9B2置本体长度5，0x14015F9E3置mode6，0x14015FA03调用公共发送。mode6要求256B；0x140166DEF设置复制次数2，0x140166E00至0x140166E50每轮128B。
格式 EB+ADDR_BE32+CHK，首地址命令 EB 00 00 00 00 14。0x14是校验，不是20字节长度。不能无依据预先丢弃一个ACK。

### 4.7 擦除策略（S+T）

0x14015E137默认D8，0x14015E193检测低16位是否为0；不对齐或剩余不足64KiB走20；0x14015E1D8步进0x1000，0x14015E1F9步进0x10000。证明4KiB/64KiB混合策略存在。实际擦除响应、尾部取整、目标地址保护需用真实目标表确认。
注意：不以首扇区擦除命令作为探测；任何破坏性动作前必须备份并验证目标。

### 4.8 NV PageCRC（S+T，禁止默认写NV）

0x140147C2F r13=对象首址+4；0x140148901至92B按类型分支清零CRC槽若干字节；0x140148930置DL=FF，0x140148932从[rsi+0x210]取N，0x140148941逐字节XOR共N次。若rsi为该对象首址且N为CRC槽偏移，实际范围是[4,4+N)，包含CRC槽的末端区域；该语义须结合对象布局和类型继续确认，不能仅凭变量名假设是XML文本长度。

0x140148969匹配U8，0x140148970写CRC至槽+3；0x14014898C/993匹配U16，0x140148999写槽+2；0x1401489AF/9B6匹配U32，0x1401489BC写槽+0。清零是按类型分支进入，不应概括成所有类型均先清零全部4B。员工3脚本对Magic、字段类型、字符串填充、CRC槽和计算范围有假设。其跳过末端CRC槽与原厂循环只有在所略字节全部为0时才可能等价；422B结果不能证明原厂实际页面格式正确。
建议用原厂工具导出/抓取NV实际写入页，逐字节对比脚本产物，明确PageCRC偏移、类型、字节序、保留字段、主/备份地址及页填充。文档cfg_nv 0x4C4000、备份0x4C6000，与历史工具全局0x56F000存在冲突，不能擅自写入。首版保留NV/二级boot/文件系统。

## 5. 固件边界、性能与升级架构

依据主仓库文件大小及V1.0既有离线哈希记录（本次原始BIN未重新上传）：
| CA034 | 大小 | 默认起点 | 数据结束不含 | 4K擦除结束不含 | 4K块/尾长 |
|---|---:|---|---|---|---|
| E31 | 2509271 | 0x28000 | 0x28C9D7 | 0x28D000 | 613/2519 |
| DSP | 74519 | 0x3A8000 | 0x3BA317 | 0x3BB000 | 19/791 |

总2583790B。115200 8N1纯载荷224.287s；1.5M纯载荷17.225s；632个4K块各30ms再增加18.96s。均未计擦除/读回/复位/协议开销，不能宣传整机20秒升级。64KiB数据分块可减少等待，但要考虑地址对齐、缓冲和掉电恢复。

原厂文档结构T_Header 256B：fixed_inf 88B、12个12B分区项及24B尾部；E31/DSP mv_length推导偏移0x78/0x84。以实板读回、magic及目标结构识别为先，不按默认地址盲写。备份首4KiB及NV，保留fixed_inf和未变分区，写回分区表前先读回固件校验。sec_mv_length=0x2000不可当boot文件大小。没有A/B实测证据，不承诺自动回滚；需保留可靠外部恢复能力。

推荐分阶段：先PC直连可恢复厂家板完成只读和抓包；再PC→MCU分块代理；量产再评估外置Flash整包暂存（需验证实际FAL容量、寿命和恢复）。PC/MCU协议CRC32与MS150 XOR分离，序号、会话ID、长度、进度和错误原因独立。MCU独占UART，进入下载/退出时恢复BOOT、串口和AT任务。接收数据成功与模组写入读回成功须分开上报。超时后不得盲目重试擦写；先读回或重新同步。

## 7. Bus Hound与实板验收

软件抓包捕获双向COM/USB I/O、时间戳及速率配置事件；驱动差异、截断、USB传输边界和实际UART波形需注意。使用至少24MHz逻辑分析仪，探头阈值符合模组IO，TX/RX/BOOTSEL/RESETN并行高阻采集，共地，不直连RS232高压侧。必要时以示波器确认模拟电平。先只读握手和读页，再在可恢复测试板使用原厂工具完成CA033→CA034。详细执行、记录格式、验收门槛见[handoff.md](handoff.md)。
