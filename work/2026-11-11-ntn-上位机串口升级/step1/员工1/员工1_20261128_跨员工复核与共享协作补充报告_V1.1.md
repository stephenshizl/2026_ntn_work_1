## 1. 本次结论和范围

现有主MCU USART3 PB4/PB5经U22连接模组UART0，PA10/PA8经反相电路控制下载/复位，硬件连接仍具备升级基础。当前实现主线调整为 **PC经RS232收包 → MCU外部Flash完整暂存与校验 → 4KiB RAM搬运 → MS150安装**，避免在目标Flash已擦除后还依赖PC实时供数。

功能目标依据用户文件清单和MCDT截图扩大为 **二级Boot、E31、DSP、NV四组件**，E31 LogMap只供PC日志解码。CA033文字清单和CA034截图对应两个发布版本，必须分别生成清单和hash，不能拼包。

Bus Hound可用于受支持COM/USB链路的软件I/O观察。推荐64MiB总缓冲、128KiB单阶段/记录上限、满缓冲停止，配合板内逻辑采集确认真实UART时序。完整操作指导已经独立编写。

## 4. 用户新增输入的落实

### 外部Flash整包缓存

OTA构建的reserved从0x212000开始，至0x800000共6,217,728 B。候选元数据扇区为0x212000/0x213000；数据区为 `[0x214000,0x514000)`，3MiB。原始Boot/E31/DSP/XML均保存，LogMap留PC。完整安装所需的NV转换页还须按已验证格式另存并关联原XMLhash。

CA034四原始文件按4KiB对齐占2,727,936 B，CA033占2,723,840 B。两版都适用候选布局；保存全部五原始文件则超过3MiB，所以不能把约3.1MB的LogMap也悄悄塞入该区。

缓存READY必须由MCU全量读回校验后提交，安装前持久记录INSTALLING。接收中断不改模组，安装中复位从已校验缓存重入ROM恢复；两类状态分开。该方案还需要FAL分区、状态日志和恢复代码实现，目前仅是设计。[外部Flash专项](NTN固件外部Flash暂存方案_员工1_V1.0_20261128.md)

### 四组件完整升级

用户截图选择CA034四组件，握手115200、烧录1500000，自动运行未选、进度0%。保存为 [原始截图](evidence/mcdt_flash_options_20261128.png)。它证明界面配置，不能作为成功升级或线上报文字节的证据。

完整功能需支持Boot/E31/DSP/NV的独立选择、发布组合与结果，不把LogMap发送到模组。首阶段可以只写E31/DSP验证通路，但能力/结果必须显示部分组件，不把Boot/NV设为永远不支持后仍宣称满足截图需求。

### NV指导和进一步反汇编

重新阅读厂商Rev1.4第7～8页3.3节，定位XML→字段序列化→CRC→擦除→02分页→主/备份完整路径。普通构造从cfg_nv_part取地址/容量，默认＋0x2000备份；对象＋4是数据缓冲而不是跳过Magic。当前XML候选423 B、PageCRC末字节42，主副本各2页，尾页167 B有效＋89 B零填充。[NV专项](NV烧录文档与反汇编核查_员工1_20261128.md)

NV原始LF文件为15,841 B，历史CRLF为16,135 B。将当前换行恢复为CRLF能够重现历史hash，避免将仓库换行差异误判成配置版本升级。发布校验仍固定实际原文件hash。

## 5. 后续Bus Hound执行基线

| 设置 | 建议 |
| --- | --- |
| 总缓冲 | 单次完整升级64MiB；受限/短场景分段用32MiB |
| 单阶段/记录 | 128KiB；79完整帧65542 B，不能仅设65536 B |
| 满缓冲 | 停止，禁循环覆盖 |
| 方向/事件 | IN、OUT、控制/串口配置、时间戳/Delta |
| 时间仲裁 | 软件看字节/配置事件，逻辑分析仪核对物理间隔和ACK速率 |
| 保存 | 原生捕获＋HEX＋控制事件＋逻辑记录＋文件hash，不能仅截图 |

先MCDT直连可恢复板UART0采原厂协议，再采PC↔MCU缓存会话及板内UART3。监控产品PC口只能看到PC↔MCU，不能替代板内UART字节证据。详细CAP01～CAP08、NV逐页比对和缓冲估算见 [Bus Hound指导](BusHound协议分析操作指导_员工1_20261128.md)。
