## 1. 核心结论摘要

1. **硬件串口升级可行性：完全可以升级。** 主 MCU（HC32F460，`U8`）通过 `UART3`（`PB4/PB5`）经 1.8V↔3.3V 双向电平转换芯片 `U22`（`TXB0104RUTR`）直连 NTN 模组（`U7`，ST1000/MS150）的下载口 **`UART0`**（Pin 32/33），且主 MCU 已完整接管 `UART_BOOT`（`BOOTSEL`）、`RESETN` 及 `VCC_ST1000` 电源使能控制。
2. **两大硬件约束决定软件架构必须采用“流式分块传输”：**
   * **上位机接口速率约束**：上位机连接主 MCU `UART1`（`PA0/PA1`）经 `U4`（`SP3232E`）转 RS232，受芯片速率限制（典型上限 120~235 kbps），不可做 1.5Mbps 透明直通，上位机侧建议固定 **115200 bps**。
   * **外挂 QSPI Flash 容量约束**：主 MCU 外挂 Flash `U11` 型号为 **`ZD25WQ16CEIGR`**（**16 Mbit = 2 MB**），而最新 CA034 版本 E31 裸固件为 **2,509,271 字节（约 2.39 MB）**，无法整包裸存至外挂 Flash。必须采用 **“上位机 115200 bps 分块流控下发 → MCU RAM 缓冲校验 → MCU 经 UART3 写入 MS150 Flash”** 的流式架构。
3. **协议核验与 MCDTV5 反汇编勘误**：经对 `MCDTV5.exe`（x64 PE）反汇编核对，确认《MS150 固件下载流程 Rev 1.4》存在 3 处关键笔误/遗漏（`EB 00 00 00 00 14` 的 `0x14` 实为 XOR 校验码而非读取 20 字节、`50 09` 漏写校验字节 `A6`、13 档波特率索引表等）。
4. **2026-11-26 补充问题（Bus Hound 监控 UART 协议）**：可行（前提是通过 USB 转串口虚拟 COM 口运行 `MCDTV5.exe`），但需调大单次捕获长度（≥65536B）与缓存，微秒级时序与波形建议配合逻辑分析仪验证。

## 2. 硬件原理图核查与可行性分析

| 功能通路 | 主 MCU (`U8`, HC32F460) | 中间调理/转换电路 | NTN 模组 (`U7`, ST1000/MS150) | 逻辑极性与升级控制说明 |
| :--- | :--- | :--- | :--- | :--- |
| **下载数据发送** | `PB4` (Pin 40, `MCU_UART3_TXD`) | `R4 (0Ω)` → `U22` (`TXB0104RUTR`, `IOB3→IOA3`) | Pin 32 (`UART0_RXD`, `NTN_UART0_RXD`) | 3.3V ↔ 1.8V (`VDDIO_AON`) 自动双向转换 |
| **下载数据接收** | `PB5` (Pin 41, `MCU_UART3_RXD`) | `R3 (0Ω)` ← `U22` (`TXB0104RUTR`, `IOA4→IOB4`) | Pin 33 (`UART0_TXD`, `NTN_UART0_TXD`) | 与 MS150 Bootloader `UART0` 完全匹配 |
| **Boot 模式控制** | `PA10` (Pin 31, `MCU_NTN_BOOT`) | `R47 (10K)`/`R48 (47K)` → `Q4` (`DTC123JET1G` 反相) | Pin 24 (`UART_BOOT`, `BOOTSEL`) | **硬件反相**：MCU 输出 **高电平** 拉低 `BOOTSEL` 进 Boot；输出 **低电平** 正常启动 |
| **硬件复位控制** | `PA8` (Pin 29, `MCU_NTN_RST`) | `R7 (10K)`/`R45 (47K)` → `Q3` (`DTC123JET1G` 反相) | Pin 12 (`RESETN`, `RESET_ST1000`) | **硬件反相**：MCU 输出 **高电平** 拉低 `RESETN` 触发复位；输出 **低电平** 释放 |
| **模组电源使能** | `PB15` (Pin 28, `MCU_NTN_PWR_EN`) | `R35 (10K)`/`R36 (47K)` → `Q7102` → `Q1` (PMOS) | Pin 18/19 (`VBAT1/2`, `VCC_ST1000`) | 高电平上电，低电平硬断电恢复 |
| **上位机通信口** | `PA0` (`UART1_RX`) / `PA1` (`UART1_TX`) | `U4` (`SP3232E`) RS232 收发器 | 外部 RS232 接口 | 受 `SP3232E` 限制，上位机侧固定 115200 bps |
| **外挂存储** | `PB1/2/10/12/13/14` (`QSPI`) | 直连 | `U11` (`ZD25WQ16CEIGR`, **2MB**) | 容量 2MB，无法裸存 2.39MB E31 固件 |

* **硬件风险与应对**：`TXB0104RUTR` 对分布电容敏感，1.5Mbps 下需示波器核验波形，必要时降档至 921600/460800 bps；进入 Bootloader 必须先拉高 `PA10`（延时 ≥10ms）再脉冲拉高 `PA8`（≥50ms）复位并监听连续 `0x55`（`'U'`）。

## 3. MS150 升级协议核对与 MCDTV5 反汇编勘误

* **通用规则**：地址/长度均为**大端序**；4KB 扇区擦对齐 4096B、64KB 块擦对齐 65536B、写入对齐 256B；`[CHK]` 为初值 `0xFF` 的逐字节 XOR；命令头与数据间延时 **30ms**。
* **关键勘误（基于 `MCDTV5.exe` 反汇编验证）**：
  1. **`EB 00 00 00 00 14`**：`0x14` 是 XOR 校验字节（`0xFF ^ 0xEB = 0x14`），不是读取 20 字节；实际读取 1 Page（**256 字节**），对应完整 `T_Header_5gNew`。
  2. **`50 09 A6`**：文档 3.1 漏写校验码 `A6`；反汇编 `0x14034A630` 证实完整 13 档波特率表：`04`=115200 (`50 04 AB`)、`06`=460800 (`50 06 A9`)、`07`=921600 (`50 07 A8`)、`09`=1500000 (`50 09 A6`) 等；目标波特率 >57600 时需先发 `55 AA`。
  3. **写保护分支**：反汇编 `0x14013E024..0x14013E298` 证实 Shark/MS150 系列发送 `575680001806000001` 与 `575680002400000200`。
  4. **二级 Boot 大小**：CA034 二级 Boot 实为 122,622B（文档注释 `0x2000`），烧录时须先 `EB` 读出原板分区表并**原样保留 `fixed_inf`**，仅更新本次烧录分区的 `mv_length`。
* **完整烧录序列**：`C0 3F`（停 U 码）→ `46 B9`（初始化 QSPI）→ `575680001806000001` / `575680002400000200`（清写保护）→ `55 AA` → `50 09 A6`（切高速）→ `EB 00 00 00 00 14`（读分区表）→ `D8`/`20`（擦除）→ `79`/`7A`（写固件，中间延时 30ms）→ NV 烧录（`20` 擦 + `02` 写 `0x4C4000`/`0x4C6000`）→ `20 00 00 00 00 DF` + `32`（回写分区表）→ `50 04 AB`（切回 115200）→ 释放 `PA10` 并复位（或发 `B0 4F`）→ `ATI`/`AT+CGMR` 校验版本。

## 4. 端到端实现方案（PC 上位机 → HC32F460 → MS150）

* **两段式流控代理架构**：PC 上位机通过 RS232（115200 bps）以 **4KB 分块 + 帧序号 + CRC32** 流控协议下发至 HC32F460；MCU 暂停常规 AT 业务线程，仅需 8~12KB RAM 缓冲校验后，通过 `UART3`（921600/1500000 bps）调用 `0x7A` 写入 MS150 Flash。
* **NV 前置解析**：由 PC 上位机离线解析 `shark_ntn_config_nv_v1.9.xml` 并计算 `PageCRC` 生成 256B 二进制块下发，MCU 无需内置 XML 解析器。
* **防变砖与耗时**：仅在全部固件块校验写入成功后才擦写 0 地址分区表；单块失败支持 3 次重传，卡死时通过 `PB15` 断电重启恢复。CA034 全量（E31 2.39MB + DSP 73KB）受限于 RS232 115200 bps 链路，总耗时约 **4.5 ~ 5.5 分钟**。

## 5. 2026-11-26 补充问题：Bus Hound 监控 UART 下载协议

* **结论**：**可以**，前提是 `MCDTV5.exe` 通过 **USB 转串口（虚拟 COM 口）** 与 MS150 通信（主板原生传统串口支持较差）。
* **关键避坑配置**：在 `Devices` 中勾选对应 `USB Serial Port (COMx)`；在 `Settings` 中将 **Max Phase 调大至 ≥65536 字节**（防止 64KB 的 `0x79` 写入包被截断）、**Buffer Size 调至 32MB~64MB** 防止 1.5Mbps 丢包；勾选 `CTL`/Serial 阶段以同步观察 `IOCTL_SERIAL_SET_BAUD_RATE` 切速时机。
* **交叉验证建议**：Bus Hound 属于 Windows IRP 层软件抓取，受 USB 1ms 轮询帧影响，无法精确测量微秒级时序或物理层波形；建议用 Bus Hound（或 Device Monitoring Studio）核对 `7A` 长度字段及完整字节流，同时在 `TXB0104RUTR` 两侧并联逻辑分析仪/示波器验证 1.5Mbps 物理信号与 30ms 延时。
