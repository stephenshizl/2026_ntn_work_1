| **1** | **分区表 `mv_length` 与 `stamp` 规则（防变砖红线）** | 全员据 PDF §2.2 计划把 `firmware.mv_length (0x78)` 改为 `0x2649D7`、把 `dsp0_code.mv_length (0x84)` 改为 `0x12317` | **4 次实测均未改 `0x78`（恒为 `0x00080000` = 512 KiB）与 `0x84`（恒为 `0x00000000`）**；唯一改动的字段是 **`0xE8` 处的 4B 小端 Unix 时间戳 `stamp`**！交叉反汇编 `0x140167F20` + `sharkNTN/flashPartition.ini` 证实 `MV_LENGTH=0x80000` 为固定搬移长度 | **避免致命变砖**：正式版严禁把 E31 文件大小 `2.5 MB` 填入 `0x78`，必须原样保留 `fixed_inf`、`rfe_nv`、`0x78=0x80000`、`0x84=0`，封口时仅更新 `0xE8` 时间戳 |

## 3. 正式版本总体架构与排期速览

- **主路径（V30 量产版，实机确认 8 MiB `BY25Q64ES`）**：
  `PC 升级工具 (四组件清单/NV 黄金编译/备份)` $\xrightarrow{\text{RS232 115200, NUPG 帧}}$ `HC32F460 外置 NOR 暂存 (ntn_fw_cache 3 MiB + 双元数据扇区 + SHA-256)` $\xrightarrow{\text{RAM 4~16 KiB 块搬运 + 读回校验}}$ `MS150 UART0 (115200 握手 → 实测选定高速档)`。
- **双兼容模式（显式协商，不静默降级）**：`STREAM_4K`（旧 2 MiB 板 / NOR 故障降级）+ `PASSTHROUGH_115200`（工厂 `MCDTV5.exe` 救援）。
- **工程落地周期**：**5 个里程碑（M0 → M4），共 4 周（20 个工作日）**——先用 3 天关闭 B08 物理波形与 `7A` 块长实测（M0），第 1–2 周完成 MCU 存储/电源/串口底座与协议引擎（M1–M2），第 3 周完成四组件端到端、掉电注入恢复与长稳压测（M3），第 4 周冻结正式 GUI 与产线 SOP 放行（M4）。
